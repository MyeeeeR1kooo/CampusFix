# #58 / #90 真实浏览器专项复跑

请先按 [D5 README](../README.md) 检出完整的 `main@6fe349f01acc5ae6f17d1059e2e8984676016ab9` 并安装它的锁定依赖。以下脚本只用于本机验收。为两个模块**各建一个全新测试数据库**，各用虚构演示用户和各自的结果目录。

1. 准备 PostgreSQL 17.11（会话 UTC），从 `backend/` 运行 `alembic upgrade head`、`python -m app.seed`，用三项 `SEED_*_PASSWORD` 环境变量提供虚构密码。#58 先保留空工单表，脚本会在截取空页面后生成 15 条合成记录；#90 则执行 [accounts-fixture.py](accounts/accounts-fixture.py) 预置一条报修人历史工单。
2. 后端从 `backend/` 启动 `python -m uvicorn app.main:app --host 127.0.0.1 --port <API端口>`，为各实例提供对应的 `DATABASE_URL`、`ENVIRONMENT=test`、`ATTACHMENT_STORAGE_PATH` 和本机 `ALLOWED_ORIGINS`。前端用 `VITE_USE_MOCK=0 npm run build` 构建，再用本机 `npm run preview`，`VITE_API_TARGET` 指向相应 API。
3. 环境变量 `BASE_URL` 设为该本机预览地址；配置测试输出目录 `RESULT_DIR`、被测仓库根目录 `REPO_DIR`、完整 SHA `SOURCE_COMMIT`、三项演示密码。Playwright 1.62.1 以 `PLAYWRIGHT_MODULE` 指向其 `index.mjs`；如使用已安装的 Chromium，设 `CHROMIUM_EXECUTABLE`。#58 还需要 `CF_PYTHON`（含项目依赖的解释器）和本机临时 PostgreSQL 的 `DATABASE_URL`。
4. 在三角色可真实登录后，从运行环境执行 `node <包内>/issues-58-90/analytics/analytics-browser.mjs` 或 `node <包内>/issues-58-90/accounts/accounts-browser.mjs`。#58 只准对专用 `analytics` 库运行；#90 只对专用 `accounts` 库造夹具，默认历史工单 ID 为 1，可用 `FIXTURE_TICKET_ID` 明确指定。隔离数据库用完可丢弃。

本目录的截图和接口证据只含虚构工单、账户和楼宇。
